# 实盘日志优化（参考 binance-rust）

## 优化目标

借鉴 `binance-rust` 项目的日志架构，提升 quantkit 实盘日志的可读性和信息密度。

## 主要改进

### 1. 统一时间戳格式

**之前：**
```
[live] bar 1724932800000 | 持仓 ["SOLUSDT 1.846652"] | 累计成交 1 笔
```

**之后：**
```
[08-30 12:50:08] INFO - 📊 Bar 1724932800000 | 持仓: SOLUSDT 1.846652 | 累计成交 1 笔
```

### 2. 结构化日志级别

引入四个日志级别，用 emoji 标识：

- **INFO** (`📊`, `🕐`, `💰`)：常规信息（bar 处理、状态检查、自检结果）
- **ACTION** (`✅`, `🟢`, `🔴`, `🔄`)：重要操作（调仓、成交、对账通过）
- **WARN** (`⚠️`)：警告信息（漂移、重试、异常但可恢复）
- **ERROR** (`❌`)：错误信息（失败、阻断性错误）

### 3. 精简冗余输出

**之前的问题：**
- 每 4 小时输出完整状态（即使未变化）
- Bar 处理日志过多，淹没关键事件
- 缺少上下文说明

**优化后：**
- 只在有持仓变化或成交时才输出详细日志
- 空仓时静默，减少噪音
- 关键决策添加 emoji 和简短说明

### 4. 异步日志写入

参考 binance-rust 的 `AsyncLogger` 实现：
- 日志消息通过 channel 发送到后台线程
- 主线程不阻塞，性能更好
- 支持自动日志轮转（按大小分割，保留最近 N 个）
- 软链接 `live.log` → 当前会话日志文件

### 5. 控制台过滤

- 只有 WARN 和 ERROR 级别输出到控制台（stderr）
- INFO 和 ACTION 只写入日志文件
- 避免正常运行时控制台刷屏

## 使用示例

### 启动自检日志

```
[08-30 00:50:05] INFO - 🕐 自检-时钟偏移: 28 ms
[08-30 00:50:05] INFO - 💰 自检-USDT 可用余额: 196.66
[08-30 00:50:05] INFO - ⚙️  自检-BTCUSDT 精度: stepSize=0.00001 minQty=0.00001
[08-30 00:50:05] INFO - 💸 自检-账户实际 taker 费率: 0.0010
```

### 调仓执行日志

```
[08-29 04:50:08] ACTION - 🟢 买入 SOLUSDT | 量 1.84800000 | 价 104.100000 | 费 0.192395
[08-29 04:50:08] ACTION - ✅ 对账通过：状态与交易所持仓一致
```

### 异常情况日志

```
[08-29 04:50:08] WARN - ⚠️  SOLUSDT 可用余额 1.84000000 低于状态 1.84800000，按真实余额卖出
[08-29 04:50:08] ERROR - ❌ 交易所无 BTCUSDT 可用余额，跳过卖出（状态漂移，请人工核对）
```

## 代码改动

### 新增模块

- `app/src/logging.rs`：异步日志记录器实现
- 导出宏：`info!`, `action!`, `warn!`, `error!`

### 修改文件

- `app/src/live.rs`：替换所有 `println!` / `eprintln!` 为新日志宏
- `app/Cargo.toml`：添加 `chrono` 依赖
- `Cargo.toml`（workspace）：添加 `chrono` 到 workspace dependencies

## 后续优化方向

### Phase B（中期）：独立日志分析工具

创建命令行工具解析日志文件，生成：
- 交易日志摘要（按天/周/月）
- 成交统计（胜率、盈亏比）
- 权益曲线可视化

### Phase C（长期）：实时日志流式传输

修复 Web UI "暂无日志" 问题：
- Web 服务捕获子进程 stdout/stderr
- 或通过 WebSocket 推送实时日志
- 前端提供日志过滤和搜索功能

## 对比 binance-rust

| 特性 | binance-rust | quantkit（优化前） | quantkit（优化后） |
|------|--------------|-------------------|-------------------|
| 时间戳格式 | `[MM-DD HH:MM:SS]` | Unix 毫秒数 | `[MM-DD HH:MM:SS]` ✅ |
| 日志级别 | INFO/WARN/ERROR | 无结构 | INFO/ACTION/WARN/ERROR ✅ |
| Emoji 标识 | 🔄 📊 🟢 ✅ | 无 | 📊 🟢 🔴 ✅ ⚠️ ❌ ✅ |
| 异步写入 | ✅ | ❌ | ✅ |
| 日志轮转 | 按大小分割 | 无 | 按大小分割 ✅ |
| 软链接 | trading.log | 无 | live.log ✅ |
| 控制台过滤 | WARN+ | 全部输出 | WARN+ ✅ |
| 信息密度 | 高 | 低（冗余多） | 高 ✅ |

## 验证方法

重启实盘服务后观察日志输出：

```bash
# SSH 到香港服务器
ssh ubuntu@43.154.120.27

# 查看最新日志（软链接指向当前会话）
tail -f ~/binanceWebsocket/logs/trading.log

# 或查看历史日志
ls -lh ~/binanceWebsocket/logs/
```

预期看到格式化的日志输出，关键事件带 emoji 标识，控制台只显示 WARN/ERROR。
